## Evidence and source decision gate

Sources consulted 2026-11-27:
- [Overture November release](https://docs.overturemaps.org/blog/2026/11/18/release-notes/), release 2026-11-18.0, schema v2.0.0 per [release calendar](https://docs.overturemaps.org/release-calendar/). Global places count 90.3 million, not California count. Places is point geometry; GERS id, names.primary, taxonomy.primary/hierarchy/alternates, basic_category, confidence, operating_status, version and sources; the old categories property was removed in September 2026. See [Places guide](https://docs.overturemaps.org/guides/places/) and [taxonomy explorer](https://docs.overturemaps.org/guides/places/taxonomy-explorer/). GERS continuity is intended but merges/splits/deletions may change identities; never reassign a disappeared ID based only on name.
- [Overture attribution and licensing](https://docs.overturemaps.org/attribution/): Places has no OSM input; the current source table includes CDLA-Permissive-2.0, Apache-2.0 and CC0-1.0 contributions. Preserve all applicable release-specific notices, including Apache NOTICE where applicable and source/license attribution; do not assume every record has the same license. [DuckDB access guide](https://docs.overturemaps.org/getting-data/duckdb/) documents release-pinned public Parquet and bounding-box predicate pushdown; no paid API required. Object range reads, bandwidth and temporary disk costs still need measurement.
- [Geofabrik California](https://download.geofabrik.de/north-america/us/california/index.html) advertises california-latest.osm.pbf at 1.2 GB (rounded publisher size, not downloaded bytes), current free SHP/GPKG links unavailable; regional PBF, extent polygon and diffs exist. Pin a dated PBF plus checksum for reproducibility; do not use public Overpass for bulk retrieval. OSM nodes, ways, relations have different ID namespaces and facilities can be duplicated across types. For ways/relations resolve actual geometry; never assume a bounding-box center is a navigable entrance. [OSM marine tags](https://wiki.openstreetmap.org/wiki/Harbour) document slipways, marine fuel and sanitary dumping.
- [OSM attribution](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines), [ODbL FAQ](https://osmfoundation.org/wiki/Licence/Licence_and_Legal_FAQ), [collective database guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Collective_Database_Guideline_Guideline): a substantial publicly used POI derivative database needs attribution and applicable ODbL share-alike and access to the derivative or changes as required. Before public use agree on a compliant means of offering that licensed derivative independently of this bounded interactive API; no unbounded SailingGo route. Keep OSM and Overture provenance/storage separate unless a documented licensing decision explicitly permits a combined derivative. No OSM-derived data relicensed as permissive. This is a design assessment, not legal advice.
- [Census TIGER/Line state boundaries](https://www.census.gov/geographies/mapping-files/time-series/geo/tiger-line-file.2025.html): candidate detailed state polygon, FIPS 06, pinned edition/checksum; include islands and state waters as represented by the chosen boundary, not merely California's bounding rectangle. Validate license and exact geometry before acquisition; explicitly document coastal and boundary behavior. Geofabrik extract polygon is not the legal state polygon.
- [SQLite R-Tree](https://sqlite.org/rtree.html) supports overlap lookup; default float32 outward rounding requires final exact coordinate predicate. SQLite driver and R-Tree build support are not in the current Go module. Existing cmd/marineplacesgen.go classifies OSM/DBW facilities, tracks source and coordinates, deduplicates, and uses regional Overpass/caches; use concepts and tests, not protected asset/cache or bulk Overpass strategy. No reuse of curated or DBW records until redistribution rights and quality established.

Provisional recommendation: evaluate Overture first for terrestrial named POIs (simpler point geometry, permissive licensing), and OSM first for marine infrastructure/parking gaps; prefer a single source if empirical coverage suffices. Do not select or conflate datasets on this evidence alone. Keep provider category mapping independent of source choice. Overture's business taxonomy is not proof of marine coverage. OSM's tag documentation is not proof of records existing in California.

## Registry and normalization (proposed version 1)

Keys are stable ASCII lowercase snake_case, 1–32 chars, maximum 32 registry entries. Version 1 is schema version, registry_revision is content digest; dataset_version changes with immutable manifest. Each entry has label (plain nonblank <=48 UTF-16 units), icon (approved glyph or short ASCII, no markup/URL), color (#RRGGBB), available boolean, native_category (general or marina). Availability means at least one validated record in active snapshot, not proof of coverage at a point. Source taxonomy mapping is an explicit release-pinned allowlist, not a substring heuristic. Initial candidate mapping (verify exact current Overture codes against pinned taxonomy, do not assume values):

| Provider key | Label | Icon | Color | Native | OSM tag candidates |
|---|---|---|---|---|---|
| fuel | Gas station | ⛽ | #EA580C | general | amenity=fuel excluding explicit marine |
| restaurant | Restaurant | 🍴 | #2563EB | general | amenity=restaurant |
| coffee | Coffee shop | ☕ | #92400E | general | amenity=cafe, verify coffee-specific scope |
| grocery | Grocery store | 🛒 | #166534 | general | shop=supermarket or grocery/convenience per reviewed mapping |
| lodging | Lodging | 🛏 | #475569 | general | tourism=hotel/motel/guest_house/hostel |
| ev_charging | EV charging | ⚡ | #15803D | general | amenity=charging_station |
| parking | Parking | P | #0369A1 | general | amenity=parking (not individual spaces) |
| marina | Marina | ⚓ | #6D28D9 | marina | leisure=marina |
| boat_ramp | Boat ramp | ↘ | #0E7490 | marina | leisure=slipway |
| marine_fuel | Marine fuel | ⛽ | #B45309 | marina | waterway=fuel or explicit seamark fuel station |

Do not fabricate missing business names: exclude unnamed named-destination records, report count; for infrastructure only, proposed explicit source-derived generic category label with notes stating unnamed mapped facility, subject to owner acceptance. No inferred fuel marine from proximity alone; no confidence score presented as verified existence. Exclude explicit permanently closed and invalid/outside records; status unknown remains unknown. Preserve data provenance, sanitize names/notes, reject prohibited controls/unpaired surrogate equivalents; measure JavaScript UTF-16 code units, not UTF-8 bytes or Go rune count. Preserve valid Unicode without splitting surrogate pairs; omit or truncate optional notes deterministically. Nonblank name <=80, notes <=1000. Stable ID poi-osm-{n|w|r}-{decimal ID} or poi-ovt-{GERS UUID}, validated ASCII 1–80. If other source IDs need hashing, hash namespaced immutable identity, not name/coordinate; persist full source ID and detect collisions. One logical feature ID across categories; dedup exact source identity and report cross-type candidates using normalized name/category/distance, never merge solely by proximity or name. Separate source IDs unless verified crosswalk; no arbitrary source priority dedup without reviewed rules. Source record identity persists when a point moves; created uses immutable snapshot UTC timestamp (changes on refresh, stable per snapshot; document as provider observation time rather than business opening date). Consider retaining first-seen time in manifest lineage if feasible; do not silently substitute current request time.

## HTTP contract (proposed; no implementation)

GET /api/poi/categories returns {version:1, registry_revision, dataset_version (null if unavailable), categories:{key:{label,icon,color,available,native_category}}}. Return registry even without dataset (available=false), no private paths. GET /api/poi/status returns {version:1, available, coverage:"California", dataset_version, snapshot_at, sources:[{name,release,license,attribution,url}], registry_revision, category_counts, notice}; no personal or operational data. Missing/incompatible/corrupt index: status and categories 200 with unavailable state, bbox 503, no weather impact. Unknown keys never synthesized from client. Future client validates registry shape and bounds, ignores unknown/malformed definitions or uses safe generic marker fallback, no HTML/SVG/arbitrary URLs; retain built-in categories separately. Provider offline: no new POIs, stale registry may be used only with stale indication; local/private saved waypoint rendering independent. New provider category should not require consumer release for online display; extending native saved categories needs separate browser and Worker design, persisted validated registry definitions and offline fallback, no private token sent to provider.

GET /api/poi/bbox?bbox=west,south,east,north&category=fuel&category=coffee&limit=200
- Exactly one bbox and optional limit; require 1–4 unique category keys, repeated category parameters; reject unknown/duplicate scalar parameters and keys, malformed escapes, nonfinite or nondecimal coordinates, out-of-range or unordered bounds, antimeridian crossing. Raw query <=1024 bytes, no unknown query arguments. Inclusive WGS84 bounds; both spans <=0.5 degrees and rectangle product <=0.125 square degrees (provisional). Partial outside-state viewport allowed, exact CA dataset filter applies; fully outside returns empty when dataset available. Oversized viewport -> 400 zoom-in; no statewide dump/pagination. Limit default 200, 1–500 across all categories. Known but unavailable categories listed in response; do not misrepresent empty results as full coverage.
- Return {version:1,dataset_version,registry_revision,categories:[...],unavailable_categories:[...],records:[{provider_categories:[...],waypoint:{id,lat,lon,name,category,notes,created}}],truncated:boolean,sources:[...],notice}. No extra fields inside waypoint. Native mapping marina if matched marine category, otherwise general; deterministic sorted keys, one waypoint per unique ID, provider_categories sorted intersection with requested keys. Order by stable waypoint ID bytewise; fetch limit+1 after exact filters/dedup, true truncation if extra; enforce encoded response <=512 KiB with whole-record truncation, never partial JSON. No pagination or automatic retries. Stable order may bias dense queries, zoom in or narrow categories. Individual record transferable via {format:"waypoint",version:1,waypoint:{...}}. Source attribution is in response and short notes for saved record; no guarantee of access, safety, current hours or routing. GPS Map's existing name/ID conflict handling remains unchanged.
- Narrow exact, unescaped, method-aware GET/OPTIONS exemptions for three paths in sailing_http_session.go; anonymous unsupported methods may remain 401 under default deny or return 405 only through exact method-reject branch, never dispatch writes; settle consistent implementation tests. Exact Origin https://gps.themauris.org, no wildcard or credentials, OPTIONS 204 only allowed origin/requested GET and approved headers (no Authorization); disallowed origin 403/no CORS, originless CLI GET allowed. Vary: Origin (and preflight request method/headers as relevant). Expose ETag and Retry-After as needed. No cookie/token verification/forwarding on public reads. Do not log viewport/query or add telemetry; inspect existing activity middleware so no new user tracking. Unknown paths, encoded variants, protected routes remain default-deny. No preview origin without separate approval.
- Parameterized queries only; per-query deadline 1s including admission; independent 4 simultaneous reads, no unbounded queue, global token bucket 8 requests/s burst 16 across POI routes; 429 Retry-After:1 on admission/rate rejection, 503 unavailable or query timeout (no internal detail); 400 invalid, 405 unsupported on exact path where deliberately rejected, 403 disallowed origin. Error JSON bounded/no-store. No per-IP tracking or unbounded map. Public GET cache max-age=60, ETag based on schema, generation and normalized query; conditional GET 304 only when available and valid, no stale-on-error; no response cache initially (index and OS page cache only). Status/categories no-store when unavailable. No query runtime upstream network.
- Explicit no-data UI distinction: empty valid bbox, unavailable dataset/category, truncated, request rejected and transient rate limit are distinct. Future GPS Map viewport debounce/cancellation, no credentials, visible attribution, transient separate layer and explicit single-waypoint save.

## Storage and operator plan

SQLite R-Tree with normal table id/source/name/coordinates/category membership plus integer row ID join is leading candidate; use R-Tree overlap constraints and exact float64 final inclusive predicate, category join and stable id order. Verify query plan, no full table scan for ordinary viewport, parameterization, cancellation, read-only mode and compiled R-Tree. Compare with standard-library sorted geographic grid / immutable file with bounded cells and offsets to avoid new runtime dependency; evaluate dense-cell worst case, file integrity, random access, disk size, portability and refresh time. Do not select Go SQLite driver or Parquet/PBF parser without sample evidence and explicit dependency/toolchain approval as applicable. No cgo or source builds assumed. Existing go.mod has no such dependencies.

Standalone cmd/poimanager (Go), acquisition and validation not imported by HTTP handlers; shared schema/normalization package possible. Dry-run plans selection, exact URL/release/checksum, projected upper bounds and output path with no download/writes; explicit apply, bounded source host allowlist, byte/time/disk/row caps, streaming, no retries unless specified, manifest schema+release+mapping+boundary checksum+source licenses+counts+rejections+hash+generator version+UTC timestamp. Explicit isolated Git-ignored cache/poi/staging or private/ path; no live caches. New immutable generation built in sibling temp directory, fsync and validate checksum/integrity, sample queries and file size; rename complete generation, atomically replace a small current pointer on same filesystem only after separate operator install approval; retain verified previous generation for rollback. Handler opens read-only validated generation, no startup downloads or writes; propose explicit process-open snapshot (restart only separately authorized), or later safe bounded reload only with approval. Missing/corrupt data isolates POI. Never overwrite a live opened index, never publish partial files. Check free disk includes input+staging+active+previous; do not prune automatically. Rollback selects previous known-good generation under owner authorization; no existing NOAA/marine cache touched.
