## Standalone manager design (not yet implemented)

1. plan: read bounded release catalog and boundary manifest, deterministic candidate set, expected bytes, reuse local verified object, explicit caps and disk requirements; dry run default. Owner approves exact objects and total cap before transfer.
2. acquire: fixed HTTPS host/release, exact expected bytes/ETag metadata, local SHA256, streamed progress/deadline/cumulative budget, no redirects or startup downloads, unique isolated staging. Retain previous source.
3. build: offline DuckDB using local pinned image, read-only source mount, bounded per-object/tile extraction, no spatial extension; Go validates WKB, boundary, reviewed taxonomy/status/confidence/identity and source licenses; stable poi-ovt-* IDs, curated marine IDs unchanged (native category equals provider key), GPS Map seven-field UTF-16/UTC contract. Partition into fixed nonoverlapping tiles (half-open edges, inclusive final boundary), deterministic sort and global duplicate-ID conflict rejection, report near-name candidates without auto-merge. Do not load statewide raw CSV in memory or reuse 100k sample cap as silent truncation; enforce explicit per-tile/global rows, bytes, wall time, disk checks; any cap violation fails generation. Separate source layers and manifests; no inferred access.
4. index: leading native Go disk-backed grid, 24-byte coordinate records plus bounded payload offsets/lengths, sorted cell/category/ID directory and separate immutable payload file (exact seven-field JSON or length-prefixed equivalent), no full names/notes resident. Deterministic bounded bbox lookup, exact coordinates and explicit truncation, no unbounded caches. Directory memory/peak RSS/payload/file descriptor use measured. Compare scan/grid and SQLite CLI comparator only; actual full payload parity, dense urban tile, wide sparse query, edge and category-selectivity, concurrency, cold/warm tests on owner Mac. Set actual row/byte/memory budgets after measured statewide inventory/owner target host capacity; don't extrapolate 4,229 sample counts. No production index format selected until tests.
5. verify: manifest with schema/release, generator revision, source hashes and license/notice set, boundary checksum, mapping revision, counts/rejections, payload/index hashes, creation time, explicit scope/available categories, integrity tests and bounded query smoke. Staging directory fsync, immutable generation only; verify files and offsets, corruption fails POI only. No current-pointer update until separate owner install approval; atomic same-filesystem pointer replacement, retain prior generation/rollback, no auto-deletion. Runtime reads validated generation without download; separate API implementation/restart approval.
